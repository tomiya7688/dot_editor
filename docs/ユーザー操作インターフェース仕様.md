# Hyper Dot Editor 利用インターフェース仕様

**状態：目標仕様（現行機能と未実装の要求を区別）**。対象：人間、ゲームエンジン、Dot Editor AIなどの自動化ツール。製品の内部開発手順ではなく、操作・発見性・配布時の利用体験を定めます。

## 1. どの利用者も同じ作品を使える

| 利用者 | 主な入口 | 最初に分かること | 出力 |
| --- | --- | --- | --- |
| 人間・初心者 | 軽量Tkinter GUI | 新規作成、描画、色、レイヤー、保存、PNG出力 | project JSON v2 / PNG |
| 人間・端末利用者 | `pixel-cli --help`、個別`--help`、コマンド説明表 | 作業のための短い実行例と引数、危険な操作 | stdout / stderr / ファイル |
| ゲームエンジン | Rust `pixel-cli` subprocess | 引数、終了値、JSONの成功/失敗、読取/編集の区別 | 機械可読な1つのJSON、非zero終了値 |
| Dot Editor AI | CLIコマンドカタログJSON＋Shell | 実装済みのコマンドと必要引数、効果、安全上の制約 | 同じCLI応答・保存形式 |

GUIはShell実行を強制せず、Shell/AI利用はGUIやTkinterを必要としません。Rust Coreが製品の描画仕様の正本です。現行GUIとPython CLIの互換経路は維持し、Rust版とPython版でコマンド構文を同一と**偽らない**こと。

## 2. 軽量GUI

- 最初の画面は**キャンバス優先**。常用操作「新規/開く/保存/PNG」「描く/消す/色」「レイヤー」を短い日本語ラベルと識別できるアイコン・ツールチップで示します。
- 細部編集・セル分割・解像度保持/破棄などは関連する文脈で説明して段階的に表示します。既存の機能を削らず、初見の利用者が多数の詳細設定を読まなくても作業開始できること。
- 画面表示サイズ・作品の論理解像度・細部破棄を混同させません。リセットや細部破棄では対象と不可逆性を明示し、キャンセルしても作品・履歴を維持します。
- キーボード利用ではフォーカス位置と選択位置を視認可能にします。メニュー、タブ、サイドバー、ダイアログを移動でき、入力欄での矢印キー・Spaceと作品編集が衝突しないこと。カーソル描画はJSON/PNGへ混入させません。
- **ヘルプはオフライン**で読めます。GUIのメニューなどから基本操作の短い案内、キーボード操作、同梱CLIの説明表へ遷移できます。未実装のキー操作やCLI機能は「使用可能」と表示しません。
- Tkinter/Pillow以外の大きなGUI/ネットワーク依存を必須にせず、起動時間・メモリは変更前後の同条件で実測します。重いWebビューアや毎回のカタログ再生成は起動時に実行しません。
- **現状**：Tkinter GUI、基本編集、メニュー・フォーカスの一部は存在します。追加の軽量導線・オフラインヘルプ、マウスなし通し操作は[GUI改善Issue](https://github.com/tomiya7688/dot_editor/issues/67)と既存#26～#30の対象です。

## 3. Shellコマンドの見つけやすさ

最低限、実際に利用できるCLIには次の入口が必要です。

```text
pixel-cli --help                 全体、利用目的別のコマンド一覧
pixel-cli pixel paint --help     個別コマンドの引数/オプション/説明
pixel-cli --version              バージョン
pixel-cli --json -p art.json status   作品を変更せず状態を取得
```

上記は**Rust版**の例です。現行Python版には別の`python -m pixel_cli --help`と`new/edit/inspect/export/palette`があり、同じ実行コマンドとして置き換えて案内しません。`pixel-cli`という名前がどちらを示すか、配布物に明示してください。

ヘルプはプロジェクトファイル・GUI・ネット接続なしで起動でき、名前、概要、引数、位置座標（0始まり）、色表記、デフォルト値、ヘルプ例、read-onlyか保存が発生するかを表示します。危険な`discard`、`--force`などは明示します。未知コマンドは使い方エラーになり、勝手に編集を実行しません。

### コマンドの説明表（表示例）

| やりたいこと | Rust CLIの例 | 動作 |
| --- | --- | --- |
| 空の作品を作る | `project new --size 16` | 新規保存。既存への上書きは`--force`時のみ |
| 作品の状態を見る | `status` | 読取り専用 |
| 点を描く | `pixel paint 3 4 "#FF8800"` | 選択レイヤーへ描画 |
| 1セルを細分化 | `detail split 3 4` | 2×2の子セルを作る |
| レイヤーを追加 | `layer add "人物"` | 新規レイヤー追加と選択 |
| PNGを書き出す | `export render -o output.png` | 画像ファイルを生成、作品JSONは変更しない |

この表は仕様の**構成例**です。完全なコマンド数・引数一覧は実行ファイル自身のコマンド定義から自動生成し、記載漏れをCIで拒否します。表の例を別の実装正本にしません。`-p/--project PATH`は各実行例の共通オプションです。

## 4. AI・ゲームエンジン向けカタログ

- **目標・未実装**：Rust CLIは`pixel-cli --commands-json`、Python版は対応する明示的な読取り専用入口から、実行版のコマンド定義をJSONで取得できます。プロジェクト不要、stdoutは1つのUTF-8 JSON、exit 0、stderrに不要な警告を出しません。
- JSONには`schema_version`、`cli_implementation`（`rust` / `python`）、`cli_version`、`commands`を含めます。各項目は`path`（空白を含まない語の配列）、`summary`、`usage`、`arguments`、`flags`、`effect`（read/create/edit/export/interactive）、`examples`とします。
- 危険な上書き・細部破棄・競合制約は追加の機械可読項目として表現します。`schema_version`を変える場合、後方互換性と追加・廃止の扱いをテストで固定します。
- 実装されていないコマンドは**出力しません**。新規batch API (#64)やrevision (#63)は実装とテストが成功した版からのみ表に現れます。
- JSONカタログは**操作を実行しない**宣言的な一覧で、AIは指定のコマンド契約・終了値・プロジェクトJSON/PNGをそのまま使用します。

## 5. コマンド表の自動生成・成果物への同梱

**目標要件（現状は未実装）**。人手でコマンド一覧をコピー・メンテナンスする運用は禁止します。

| 配布単位 | 同梱する説明表 | 参照する実装 |
| --- | --- | --- |
| 現行Windows GUI＋Python CLI ZIP | Python版`COMMANDS.md`＋`commands.json`＋短い操作ガイド | Python `argparse`定義 |
| Python wheel / sdist | インストール後または展開後に取得可能な同じPython版説明表 | パッケージ化されたPython CLI |
| 将来のRust Windows/Linux/macOS CLIアーカイブ | Rust版`COMMANDS.md`＋`commands.json`＋短い使用例 | Rust `COMMANDS`定義 |
| GUIヘルプ画面 | 実際に同梱したCLI版の説明表をオフラインで開く | 同梱資料、起動時の外部ダウンロードなし |

同じアーカイブに複数実装のCLIが入る場合は`docs/cli/python/`と`docs/cli/rust/`に分け、入口で種類・バージョンを示します。混同させる`COMMANDS.md`だけの曖昧な表は作りません。

生成は**ビルド時、最終アーカイブを作る前**に行い、成果物内の表と実コマンドの個数・構文・フラグ・バージョンを照合します。署名・attestation対象は**表を含んだ最終アーカイブ**であり、署名後に説明表を差し込んではいけません。既存の配布停止条件（#55）を維持します。各成果物から表が消えた場合はCIを失敗させます。

## 6. 受け入れ条件

1. 人間がオフラインでGUIの基本操作を確認でき、保存から再読込までの導線がある。
2. GUI・CLI・ゲームエンジン・AIが同じJSON v2/PNGを意味的に扱える。GUIの表示調整やヘルプ閲覧は作品・履歴を変えない。
3. Rust/Pythonそれぞれ実行版のコマンド説明表が**一つの正本から自動生成**され、個別`--help`と一致する。
4. 配布ZIP・wheel・sdist・Rust OS別配布アーカイブを実際に展開し、同梱資料の存在・実CLIとの一致を検証する。
5. 説明表欠落・古い版・未実装コマンド混入・危険な操作の説明欠落時は**ビルド/CIがfail-closed**で停止する。
6. Python 3.10〜3.14とRust release、実バイナリsubprocess、Windows配布検査を維持。OS実画面のE2Eはheadless smokeと区別する。
7. 利用者向けの操作説明は、リポジトリへの変更・共同作業・CIレビュー規則とは分離する。

関連：自動コマンド表 [#66](https://github.com/tomiya7688/dot_editor/issues/66)、軽量GUI [#67](https://github.com/tomiya7688/dot_editor/issues/67)、Rust配布 [#38](https://github.com/tomiya7688/dot_editor/issues/38)。

## 7. GUI操作の受け入れ仕様（次期要件、#67）

人間が目的へ到達できることと、保存データを壊さないことを必須とする。現在のTkinter GUIの既定窓は1040×740、最低窓は900×640、メニューのトップ階層は6件。下記の**ヘルプ(H)・新規の導線・未保存確認の統一**は設計であり、今すぐ利用できるという案内ではない。

| ユーザーの目的 | 最短の操作導線（目標） | 成功時に変わるもの |
| --- | --- | --- |
| 新しい作品を始める | 「新規」→必要なら保存確認→新しい無題作品 | 作品・選択・履歴（確認後のみ） |
| 既存作品を続ける | 「開く」→保存確認→JSON選択 | 検証済み作品へ切替。失敗時は旧作品を保持 |
| 絵を描く | ツール・色・セルを選択→描画 | 作品の画素とUndo履歴 |
| レイヤーで描き分ける | レイヤー選択→描画 | 選択レイヤーの作品状態 |
| 細部を編集する | 「細部・解像度」を展開→分割/保持/破棄 | 明示した対象の細部と履歴 |
| 作品を残す | 「保存」→初回だけ保存先を選択 | 作品JSON v2。成功後に未保存表示を解消 |
| 画像を使う | 「PNG書出し」→保存先を選択 | PNGのみ。編集用作品JSONは変更しない |
| 使い方を調べる | 「ヘルプ(H)」→基本/キーボード/CLI | 作品・履歴・未保存状態は**変更なし** |

「新規」と「作品をリセット」は別の操作。未保存の作品を捨てる可能性がある場合は**保存・破棄・キャンセル**を提示し、既定はキャンセル。エラーやキャンセルで元の作品・選択レイヤー・履歴・保存先が変わらないこと。

### オフラインヘルプの品質

- 初回GUI起動にネット接続は不要。ヘルプはその版に同梱した文章だけを読取専用で表示し、Shellコマンドや外部URLを実行しない。
- 「CLIコマンド表」は**同梱された実装**（現行WindowsはPython版）とバージョンが一致する場合のみ表示。Rustの未配布・未実装コマンドをPython版の説明として出さない。
- カタログが壊れた場合はわかる日本語でエラーを表示し、勝手に別版の表で置き換えない。
- メニューにはヘルプ(H)を追加し、フォーカス・検索・Escでの復帰、キーボードでの全項目到達を保証する。入力欄のSpace/矢印キーはキャンバスの描画に作用しない。
- 現行のAlt/F6等の操作は維持し、キーボードのセル移動/Space描画の**将来要件**を実装前に使用可能として掲載しない。

### GUIの軽量性をどう判定するか

Tkinter/Pillowを維持し、起動にブラウザエンジン、ローカルWebサーバー、常駐daemonや追加のネットワーク取得を要求しない。画面の大部分はキャンバス、基本描画/色/レイヤー/保存は常に到達可能にする。最低窓900×640とDPI拡大で保存・描画が見切れず、スクロール/Tab/Altメニューから到達できること。

起動時間・アイドル時メモリは同一条件で変更前後5回以上測定し、差を報告する。数値が測れなかった項目は未検証とし、GUIのheadless smoke成功を実画面操作成功と取り違えない。

具体的な画面状態・異常系・E2Eは[軽量GUIの設計](design/lightweight-gui.md)に定義する。CLIコマンド表の生成・同梱は[#66](https://github.com/tomiya7688/dot_editor/issues/66)が先行し、GUIは同じ版の資料を読むだけにする。
