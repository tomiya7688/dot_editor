# Rust Coreの移植（Issue #35）

RGBAラスタのpaint・erase・sample・4近傍fillを実装済み。
ResolutionFieldは任意解像度の画素中心で読み出し、表示解像度を変えても保持中の細部へ復帰できる。
局所パッチによるpaint・erase・discard_detailと細部判定を実装済み。preserveは未飽和の色差分を保持し、discardは対象セルだけを置換する。編集前のスナップショットは保持され、予算超過時は変更を適用しない。
Rust Coreに論理解像度と保持フィールドをまとめたCanvasを追加済み。任意解像度描画、paint・erase・解像度変更・局所分割のUndo/Redo（最大50操作）を扱い、破棄操作も履歴から復元できる。
4子セルを個別に読み書きでき、collapse後も細部は保持される。
保持フィールド上の4近傍fillを実装済み。変更前の論理RGBAで領域を判定し、preserve/discard・分割セルの親色に対応する。同色discardも領域を探索し、細部を持つセルだけを対象にする。塗りつぶし全体を1回でUndo/Redoでき、途中の予算超過時は画像・履歴とも変更しない。細部のない全面fillと全面discardは単色フィールドへまとめ、セル数に比例したパッチ増加を避ける。部分fillには既存のパッチ予算が適用される。
セル分割の領域操作を実装済み。長方形の範囲・子セル描画の予算・分割記録の上限を事前に検査し、領域全体を1回でUndo/Redoできる。展開済みセルは変更せず、折りたたみ済みセルは親色・子セルを保持して再展開する。変更なし・エラー時はRedo履歴も保持する。

# Rustの保存・画像互換（Issue #36）

単一Canvasのversion 2 JSON書き出しを実装済み（`Canvas::to_json`）。表示画素、保持パッチのclip/extent・元画素・未飽和の色差分、解像度ごとの分割親色・展開状態、現在の解像度の子セル情報を出力する。書き出しでは画像・Undo/Redo履歴を変更しない。
Rust→Python読み込み・再保存の互換検証をCIに追加済み。透明画素の隠れたRGB、非正方形、細部保持・局所破棄、色差分のクリップ、展開／折りたたみ、別解像度の分割を検証する。
Rust側のJSON読み込みを実装済み（`Canvas::from_json`）。version 1の子セルもversion 2へ移行でき、保持パッチを正確な元画像範囲で復元する。重複キー、128コンテナを超える深さ、不正な画素・座標・色差分、パッチの重なり・欠落、分割の上限超過、表示画素／子セル情報の不一致を拒否する。入力は最大256MiB、読み込み後のUndo/Redoは空。レイヤー付きJSONは未対応のため明示的に拒否する。
Pythonで作成・再保存した文書と旧形式をRustへ読み戻す検証もCIに追加済み。
次はレイヤー操作と合成を移植する。PNGレンダリングも未移植。JSON書き出しは既存形式の描画サイズ・有理座標上限に従う。保持解像度の要約はu32の上限まで、画素サンプリングは正確な範囲を使う。

# Rustの保持パッチ切り抜き検証（Issue #35）

細部を保持したまま局所編集を繰り返すと、切り抜いた画像の原点と元画像の原点が異なります。画素境界のずれや色の損失を検出するため、`field_patch` に6テストを追加しました。3×2の元画像を非単位の有理数範囲へ配置し、半画素格子の全210矩形と、包含関係にある全4,410組の連続切り抜きを整数の期待値と照合します。透明画素のRGB、未飽和の色差分、保存用データからの復元、単色の保持予算、必要な元画素が変わらない場合の画像共有も確認します。今回の確認範囲では不具合は見つかっておらず、演算処理は変更しません。

利用者の直接操作はありません。通常どおり細部編集と保存を行ってください。開発者は `cargo test --manifest-path rust/Cargo.toml --lib field_patch` を実行してください。6件が成功し、連続切り抜き後も元画像上の画素境界と未補正の色が維持されることを確認できます。最適化後の確認には `--release` を追加してください。

内部の切り抜きは現在の表示範囲内にある正の面積の矩形を受け取り、標本取得は表示範囲内の座標を受け取ります。呼び出し元の交差・包含検証を省略できるAPIではありません。この検証は固定の小画像と有理数範囲に対するもので、任意入力すべての網羅、確保失敗の注入、JSON形式全体の予算・分割検証、実GUI操作は含みません。次はJSON読込での保持パッチの被覆検証をレビューします。

# CLIの整数座標変換

色を含む `--paint`・`--paint-child`・`--fill` は、座標も文字列として解析されるため、整数だけを受け付ける共有APIへそのまま渡すと失敗する。CLI側で親・子座標を整数へ変換し、単発・対話の両経路で同じ操作を利用できるようにした。小数・非数値は拒否し、失敗した編集は保存しない。

利用者は通常どおり `python src/pixel_cli.py edit --project 作品.json --paint 2 1 "#123456"` を実行してください。アプリは指定した画素を塗って作品を保存します。不正な座標では終了値2と診断を返します。対話モードでは後続行を続けられますが、エラーがあったセッションの終了値は2になります。

回帰確認では `python -m unittest discover -s tests -p test_cli_coordinates.py` を実行してください。APIへ渡す実際の座標型、不正入力時の元JSONと別出力先の保護、対話での失敗後の再編集を検証します。

# 共有APIの整数入力検証

共有APIで小数を切り捨てたり真偽値を座標として受け入れたりすると、呼び出し元の指定と異なる画素を編集する。親座標・子座標・領域寸法は組み込みの `int` 型だけを受け付け、文字列・小数・真偽値・無限大などは編集前に `ValueError` で拒否する。単一作品とレイヤー作品の編集・照会で同じ検証を使用する。

APIを呼ぶ開発者は `api.paint(2, 1, (255, 0, 0, 255))` のように整数を渡してください。CLI利用者の実行方法は変わらず、CLIが座標文字列を整数へ変換します。拒否した操作では画素・分割状態・Undo/Redo履歴を変更しません。直接利用する開発者は `ValueError` を処理し、座標の型と範囲を修正してください。

検証には `python -m unittest discover -s tests -p test_command_integer_inputs.py` を実行してください。型の拒否だけでなく、操作失敗後に既存のUndo/Redoを実行できることを確認します。

# 領域分割の一括Undo

セルごとの分割を繰り返すと、領域全体を戻すためにUndoを何度も実行する必要があります。単一作品・レイヤー作品ともに、領域分割の候補を作ってから1回だけ確定します。型・境界・描画予算・保持記録の上限を検証し、途中失敗や変更なしの場合は画像と既存のUndo/Redoを維持します。再展開するセルの親色・子画素は保持し、記録を二重に数えません。

APIを使う開発者は `api.split_region(0, 0, 2, 2)` を呼んでください。戻り値は新たに展開したセル数で、作品モデルの `undo()`・`redo()` は領域全体に作用します。レイヤー作品では選択中の層だけを編集します。CLI利用者は `python src/pixel_cli.py edit --project 作品.json --split-region 0 0 2 2` を実行してください。アプリは領域を分割して保存します。Undo/Redo履歴はJSONへ保存しないため、CLIを起動し直した後の履歴復元は行いません。

分割候補の辞書は必要になったときに1回だけ複製します。単一キャンバスの対象セルをA個、既存の分割記録をS件、新規記録をK件、保持画像のパッチをT件とすると、色の参照を含む候補構築はO(A + S + K×T)、追加の候補領域はO(S + K)です。保持記録と画像パッチはそれぞれ最大4096件です。これはソース構造上の計算量であり、実行時間の改善率は未計測です。

検証には `python -m unittest discover -s tests -p test_region_split.py` を実行してください。一括Undo/Redo、途中の予算超過と色参照例外、展開済み領域、混在領域、親子色、入力・描画予算、非選択レイヤーの保護を確認します。

# 保持フィールドの名前付きパッチ

局所パッチの表示領域・元画像領域・画像・色差分を添字だけで扱うと、読み違えや変更漏れを見つけにくくなります。内部のパッチを `Tile` の `clip`・`extent`・`image`・`offset` で表し、描画・編集・保存の参照先を明確にします。作品のJSON形式とCLIの操作方法は変更しません。

利用者の直接操作はありません。通常どおり作品を編集・保存してください。アプリは有理数の元画素境界と未飽和の色差分を保持し、解像度変更後も細部を描画します。内部APIを使う開発者は、パッチを直接構成する場合に `Tile` と `Fraction` の領域座標を使用してください。名前付き記録のフィールドは再代入できませんが、Pillow画像自体は可変なので、共有後の `image` は変更しないでください。

細部判定は重なるパッチが2件見つかった時点で終了し、候補全体のリストを作りません。パッチ数をT件とすると最悪の探索量はO(T)、探索に使う追加領域はO(1)です。実行時間の改善率は未計測です。

検証には `python -m unittest discover -s tests -p test_resolution_field.py` を実行してください。入力画像の独立性、切り抜きの画素境界、差分の可逆性、独立した色計算と描画の一致、JSON復元、細部判定の早期終了、保存予算超過時の元状態保護を確認します。既存の解像度・細部保持・RustとのJSON互換検証も継続します。
