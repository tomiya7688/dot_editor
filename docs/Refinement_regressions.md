# セル分割の保持・破棄と回帰検証

Issue #3 のセル分割モデルを、Issue #6 の任意解像度と組み合わせて検証します。

## 子セル編集の境界

明示的に分割したセルの親色と子セル色は独立です。`paint(..., child=(cx, cy))` と `erase=True` を使った子セル編集は、4つのどの子セルでも親の保存色を変更しません。`detail_policy="preserve"` / `"discard"` のどちらにも適用します。親を変更する操作では `child` を省略します。

親の中心が右下の子セルの境界に位置しても、子セルへの色差分や置換を親の保存色へ適用しません。他の解像度での通常の粗い編集については、既存の色差分による保持動作を維持します。

## 別解像度で保持した情報の破棄

ラスターパッチが単色でも、別解像度の分割セルには独立した親色が保存されている場合があります。`has_detail_at()` はその保存情報も検査し、局所破棄や同色のdiscard描画・塗りつぶしを誤って変更なしと判定しません。

対象セルへ完全に含まれる分割情報は破棄します。部分的に交差する分割では、対象領域に中心が入る親色の差異を更新し、領域外の情報を残します。境界は左・上を含み、右・下を含まない範囲です。再実行しても破棄する情報が残っていなければ変更なしとなり、余分なUndo履歴を作りません。

破棄は選択中のレイヤーと指定領域だけに適用されます。別の解像度へ移動した後でも破棄済みの親色が復活しないこと、Undoで破棄前の状態へ戻れることを検証します。

## 回帰テスト

```bash
python test_refinement.py
```

22件のテストで次を確認します。4子セルと2ポリシーの組み合わせは各テスト内のsubTestでも検証します。

- 子セルの描画・消去後の親色、兄弟セル、対象外領域の保持。
- 展開・折りたたみ、7×5 / 23×17への解像度切替、JSON保存・再読込、再展開。
- 別グリッドの親色のみの情報、完全包含・部分交差・境界上の局所破棄。
- 同色のdiscard描画・塗りつぶし、破棄の再実行、Undo/Redo、失敗時の状態・履歴維持。
- 旧JSONの移行、複数レイヤー、PNGの画素一致。
- GUIの実ハンドラーをウィジェット・ファイル選択ダイアログのモックと組み合わせた操作。ズーム・パンを経た右下子セルへの描画、再合成、Undo/Redo、保存・読込。
- 標準入力を閉じた実CUIプロセスでの保存・解像度往復・inspect・PNG出力と破棄済みデータの非復活。

GUIテストは画面やOSダイアログの目視確認ではありません。CIではPython 3.10 / 3.11 / 3.12 / 3.13 / 3.14の全環境で、既存評価・バックエンド・CUI・解像度テストに加えて実行します。

プロジェクト形式（version 2）やCUI構文は変更しません。Command API全体の統一などIssue #4の残作業は別単位です。
