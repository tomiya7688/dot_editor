# Dot Editor AI — 学習・評価・PoC計画 v0.2

> 状態: P4の**比較実験計画（未実行）** / 2026-11-04 / 親Issue [#69](https://github.com/tomiya7688/dot_editor/issues/69)  
> 対象: モデル学習・品質評価・実験管理の担当者。上位仕様は [設計書](設計書.md)、画像非参照の実行境界は [ActorとRunnerの実行契約](ActorとRunnerの実行契約.md)。  
> 目的: **画像を見ることなく、文章から描画操作を学んだ結果、未見文章でも上達するか**を再現可能な実験で判定する。

## 1. 学習問題を正確に定義する

- 入力: 学習データは `(文章, 画像)` の対応ペアだけ。コマンド実演・正解操作列・画像→コマンドの逆解析結果を教師として使用しない。
- 行動者: Actorは文章、既知のキャンバス寸法/レイヤー、自己操作履歴、CLI成否、制限されたスコアだけを見る。**目標画像も生成画像も見ない**。
- 環境: Dot Editor Rust CLIがコマンド列を実行し、作品JSON/PNGを作成する。
- 報酬: 隔離されたEvaluatorが生成PNGと参照画像/文章から計算する。**Actorへ送るのは数値だけ**。
- 学習対象: 状態からコマンドを選ぶ確率方策 `πθ(action | text, stage, own_history, nonvisual_metadata, feedback)`。
- 狙い: 訓練中の参照画像の復元ではなく、**未見の文章から妥当な絵を再現性ある手順で描けること**。

学習終了後の推論時に参照画像は存在しない。評価器は生成PNGと文章の一致度等を測って候補を選べるが、推論時のActorにも画像を渡さない。

### 制約による難しさ

従来の描画強化学習には目標画像/キャンバスをモデルに見せる手法がある。それと異なり、このActorは画像を見て誤差を修正できない。したがって、**報酬が疎で、操作列が長く、探索空間が巨大**になる。画像を直接出す生成モデルと同等の品質や収束速度を保証しない。

`64×64 = 4,096`セルに対し、`512×512 = 262,144`セル。単純な一画素操作だけで高画質を目指すと効率が悪いため、**操作の抽象化・バッチ化・段階学習が成功条件**になる可能性が高い（効果は未検証）。

## 2. 検証する学習方式

### 2.1 教師コマンドなしで開始する

初期方策には正解操作列を使えない。PoCで比較する候補は以下。

| 候補 | 初期化 | 利点 | 懸念 |
| --- | --- | --- | --- |
| A: 文法制約付きランダム方策 | 既存コマンド表＋ランダム値 | 最低限の比較基準 | 有効な絵に届く確率が小さい |
| B: 文章の規則的な解釈＋探索 | 「赤」「左」等の**テキストのみ**から初期座標/色の候補分布を組む | 序盤の探索空間を減らせる | 人手の意味ルールが多いと学習成果と混同する |
| C: 画像を見ないテキストモデルを初期方策に利用 | 文章理解は文章だけで行う。**画像対応の事前学習をActorに持ち込まない** | 日本語の文理解と長い計画が容易になる可能性 | 外部事前学習の出典/ライセンス/追加データの扱いが必要 |

最初はAとBを必ず比較。Cは**事前学習済みテキストのみモデルの利用を許すか**を別途決めてから実施し、モデル出所と重みを記録する。どの方式でも画像を見せない。

### 2.2 候補探索と実際の重み学習を分離

1. **探索フェーズ**: 同じ文章と同一snapshotから、複数の編集候補を生成してスコア比較（best-of-K）。
2. **学習フェーズ**: 採点済みの自己生成ロールアウトから、条件付き行動の確率を更新する（方策勾配、グループ相対報酬、または保守的な自己蒸留を比較）。
3. **評価フェーズ**: 重みを固定し、**新しい文章・画像の組**を使って成功率を測る。

探索だけでスコアが上がっても「モデルが学習した」とは呼ばない。**重み更新前後の未見文章で改善が再現した場合のみ、操作学習による改善と判定する**。

### 2.3 1エピソードの擬似手順（設計）

```text
pair ← Dataset.sample(train_split)
prompt ← pair.caption
reference ← Evaluator側に隔離（Actorへ渡さない）
checkpoint ← Runner.create_blank_project(mode)

for stage in curriculum(mode):
    actor_observation ← prompt + stage + own_history + safe_execution_feedback
    candidates ← Actor.sample_K(actor_observation)
    for candidate in candidates:
        draft ← Runner.clone(checkpoint)
        valid ← Validator.check(candidate)
        if not valid:
            score ← no_score, error ← INVALID_ACTION
        else:
            Runner.execute(draft, candidate.ops)
            png ← Runner.render(draft)         # Actorへ返さない
            score ← Evaluator.score(reference, png, prompt)
        Trainer.record(candidate, score, error, cost)

    checkpoint ← select_best_valid_or_keep_previous()
    Actor.receive(quantized_score_and_status_only)
    if budget_exhausted: break

Trainer.update_policy_from_own_rollouts()
Evaluator.update_if_allowed_only_on_separate_validation_cycle()
save checkpoint + command_trace + model/evaluator/version metadata
```

上記は工程を表す擬似コード。Python/Rustに未実装であり、学習APIの完成宣言ではない。

比較条件は**同じEvaluator問い合わせ回数・同じネイティブ編集コマンド数・同じ実行時間上限**を原則とする。K候補を増やした実験が単に多くの計算を使った効果と区別できるようにする。

### 2.4 信用割当と探索安定化

- ステージ単位の相対報酬を、同じ基準snapshotから生成した候補間で比較する。
- `advantage = candidate_score - group_mean_score` のような候補群基準を提案。スコアをカテゴリ/対象画像に跨って比較する前には標準化方法を固定する。
- 無効コマンドと評価器障害を混同しない。無効コマンドは実行失敗、評価器障害は報酬欠損として処理する。
- 長いコマンド列をすべて同じ報酬で学習する方式と、**段階別に分ける方式**を比較する。先行する初期コマンドへの信用割当が誤る可能性を検証する。
- 同じ描画を繰り返す、同じ色を塗り直す、レイヤーを無限に追加する等の**ループはコマンドコスト**として計測する。
- 画質が少し下がる探索を完全に禁止すると局所最適に閉じ込められる。採用済みの最良作品は維持しつつ、未採用の試行自体を許す。

## 3. 学習段階（カリキュラム）

カリキュラムは**プロンプトの難しさ**と**編集解像度**を別軸で進める。文章の難易度は文字列と語彙から計算してよいが、画像の内容を解析したラベルをActorへ送らない。

| レベル | 文章条件の例 | 学習目標 | 先に確認すること |
| --- | --- | --- | --- |
| C0 | 「背景を赤にする」 | 色と塗りつぶし、終了判定 | テキストによる色指定を学ぶ |
| C1 | 「白地に赤い四角」 | 形/位置/前景背景 | 画像由来の操作教師なしで形が改善する |
| C2 | 「左に青い円、右に赤い三角」 | 空間関係、個数、重なり | 未見の左右/数/色の組合せ |
| C3 | 「緑の木と小さな家」 | 複数物体、部品構成 | 全体の配置を壊さず細部を増やす |
| C4 | 長文・複雑な情景 | 構図/質感/文の条件 | 単純課題の成功後のみ挑戦 |

### 64×64モデルの描画ステージ案

```text
4×4  : 配色・背景・大まかな重心
8×8  : 主要物の位置
16×16: 大まかな輪郭
32×32: 形の整合・部品
64×64: 最終のドット表現・色の整理
```

- 最終ネイティブ出力を64×64に固定。64×64画像を大きく拡大表示しても元の学習解像度は変わらない。
- ステージ用の教師画像をActorに渡さない。Evaluatorが**同じ参照画像から固定された縮小規則**で評価用画像を作ることは許す。
- 縮小時のアルファ・ガンマ・輪郭の扱いを固定する。小さい画像の曖昧な輪郭を過剰に罰しない。
- `detail preserve`を基本にし、`detail discard`は明示的に許可された試行に限る。作品JSONの意味的同等性と保持/破棄をテストする。

### 高画質モデルの描画ステージ案

```text
8×8 → 16×16 → 32×32 : 構図/背景/人物や物体の大枠
64×64 → 128×128     : 輪郭と大きな色面
256×256               : 陰影・部品の細部
512×512以上           : 十分な細部を追加できた場合にのみ解禁
```

- 高解像度化そのものは**新しい画像情報を増やさない**。最近傍拡大しただけの画像と比較して、実際に細部が増えているかを評価する。
- 「高画質」を**高い画素数**と同一視しない。構図、自然な階調、質感、背景の整合、テキスト適合を測る。
- 現行Rust CLIの単一セル編集と領域fillだけでは、滑らかな写真風表現に必要なコマンド数が増大し得る。形状操作を追加する場合は本体側の汎用機能として検討し、Actorの画像非参照条件を維持する。
- Pixel64のモデル重みをHighResへコピーして「別モデル」を名乗ることは確定要件の解釈を確認するまで行わない。**初期案は重み/データ/評価を独立**とする。

## 4. 報酬の詳細設計

### 4.1 計算と配信を分離する

Evaluatorは各候補に対して複数の内部指標を計算できるが、Actorへ返すのは**総合1スコア（粗いbucket）を既定**とする。

```text
Evaluator内部:
  score_ref      = 参照画像への一致度（学習のみ）
  score_text     = 文章に書かれた内容への適合
  score_shape    = 大まかな構図/輪郭（適用できる画像のみ）
  score_style    = Pixel64のドット表現 / HighResの知覚品質
  penalty_valid  = 無効操作・破壊的操作
  penalty_cost   = 使ったネイティブ操作数/評価回数/時間

  raw = normalized_weighted_sum(scores) - penalties
  bounded = clamp(raw, configured_min, configured_max)
  actor_feedback = quantize(bounded)  # 事前登録した精度のみ
```

- 各指標は最初から`[0,1]`等へ正規化し、欠損を0点扱いしない。適用可能な指標のみを集計し、使った指標と重みを評価器ログに記録する。
- **Pixel64**: 色、輪郭、アルファ、ドット構造、意味一致を重視。写真向け知覚指標をそのまま主指標にしない。
- **HighRes**: 文章一致、構図、局所質感、人間の主観品質との整合を重視。単一の参照画像への画素誤差だけで不当に罰しない。
- **不正操作ペナルティは画像評価と別**に管理。評価器が止まったら欠損扱いで、画像品質の負点にしない。
- 重み・bucketの精度・ステージ内評価回数は事前登録し、試験の途中で都合よく変更しない。

### 4.2 学習時と推論時の採点器

- **学習時**: 参照画像＋文章＋生成PNG。参照一致と文章適合を含められる。
- **推論時**: 参照画像なし。生成PNGとユーザー文章の一致・見た目の品質・操作コストのみ。参照類似度は計算しない。
- 画像比較のための特徴量/知覚距離は**Evaluator内部に閉じる**。それが外部学習済みモデルを用いる場合、学習データ条件、権利、ライセンスを検証する。
- 評価器の出力を自然言語の「左を赤く直せ」のような画像由来の修正指示に変換しない。
- 1スコアから必要なら**数ステージ単位のスコア**まで段階的に増やす。座標別・画素別スコアの連続問い合わせを禁止する。

### 4.3 評価器のハック・ドリフト対策

- 常時更新される採点器は、Actorに悪用される隙を作る。**固定された評価器版**を基準として保存し、採点器の更新は別のオフラインサイクルで行う。
- 「ほぼ単色なのに高得点」「微小な点だけを増やすと高得点」などを検知するため、画像の簡単さ・多様性・人間の目視評価を併用する。
- 同じ評価器で候補選択も最終合格判定もすると過学習する。**学習用Evaluatorと独立のholdout評価/人間評価**を用意する。
- スコア情報の漏えいを抑えるため、同一参照画像への質問回数上限、bucket化、評価項目数上限を試験する。ただし数値スコアから一切情報が漏れないという保証はしない。

## 5. データセットの作成と分割

データ単位は画像+文章ペア。作者、作品、ライセンス、重複group、splitの管理情報は保持してよいが、**学習に使うActorへの観測ではない**。

1. 画像の権利/利用条件/出典を確認。公開不可・個人情報含有のデータは使用を避ける。
2. 64×64の資料と高画質資料を分離。画像を正規化する場合、リサイズ/色空間/アルファ処理を版固定する。
3. 同じ作品の差分、別解像度、近似重複、同一作者作品の重複をgroup化し、train/val/testで分離する。
4. テキストの完全一致・言い換え・物体名・位置関係の組合せによる**未見プロンプト**を定義。画像だけ未見で文章がほぼ同じという漏れを避ける。
5. 実験コードが画素を読み出すのはDataset/Evaluatorだけ。ActorとTrainerの実行環境に画像ディレクトリをmountしない。
6. **評価対象のサンプルIDを秘密にする**。学習にない回答例や外部テスト画像がモデルに流入していないことを確認する。

小規模の単純図形画像をプログラムで作る実験も認めるが、Actorへ提供する教師データはその完成した画像と文章のペア**のみ**。作図プログラム・幾何パラメータ・正解コマンドを教師として流用しない。

## 6. 比較実験とアブレーション

**全実験の前に**seed、データsplit、Evaluator版、使用するRust CLI SHA、候補数、最大コマンド数、評価問い合わせ回数、計測機器、判定方法を登録する。

| 実験ID | 比較 | 調べる理由 |
| --- | --- | --- |
| EXP-01 | ランダム / 文法制約付きランダム / テキスト規則初期化 | 文章と形/色の学習ができるか |
| EXP-02 | 1候補 / K候補（同一総予算） | 候補探索の本当の利得 |
| EXP-03 | 最終報酬のみ / ステージ別集約報酬 | 疎な信用割当を改善するか |
| EXP-04 | 全64×64から直接学習 / 4→8→16→32→64 | 階層カリキュラムの効果 |
| EXP-05 | 学習なしbest-of-K / 同じ予算の方策更新あり | **モデルが学習**して未見文章へ一般化するか |
| EXP-06 | 単一採点器 / 複合指標＋独立holdout | 報酬ハックを減らせるか |
| EXP-07 | ネイティブCLI単発 / 安全なバッチ | 出力の同一性と実行コストの改善 |
| EXP-08 | HighResの単純拡大 / 同じ初期作品から追加編集 | 解像度ではなく新規細部の価値 |
| EXP-09 | スコアの精度/回数を制限した学習 / 制限が緩い試験用環境 | 数値フィードバック量と精度/漏えいリスクの関係 |

**単にKを増やす実験と、方策が一般化する実験を混同しない。** 予算同一の対照群と、モデル重みを固定した推論条件を必ず用意する。

## 7. PoCの段階と進行ゲート

| 段階 | 課題 | 成果物・次段への条件 |
| --- | --- | --- |
| PoC-0 | 本体CLI/操作契約/画像隔離 | 不正コマンド拒否、作品再生、境界テストに成功。**本体v1完成後に実施** |
| PoC-1 | 2〜4色の単純図形、低解像度 | テキスト/色/位置の未見組合せで、同一予算のランダム/固定方策を上回る |
| PoC-2 | 16×16→64×64のドット絵 | 未見文章で、階層学習と重み更新がベースラインを上回る |
| PoC-3 | 独立HighResモデル、128→256 | 単純拡大基準を超えて意味一致・構図・追加細部が改善 |
| PoC-4 | 512以上の高画質 | 予算、画像品質、人間評価が事前合意基準を満たす場合のみ |

品質判定は、固定テストセット、複数seed、信頼区間、**人間のblind比較**を組み合わせる。具体的な合格閾値はPoC-1前にベースラインと計算予算を計測して設定する。テスト結果を見た後に閾値を下げて合格にしない。

### 最低限報告する測定値

- `prompt_alignment`: 未見文章の要求が絵に表れている割合（意味・位置関係・個数）。
- `human_preference`: blind比較で基準より好まれた割合。評価者にモデル名・スコアを明かさない。
- `valid_action_rate`: 有効編集操作の割合（これだけでは絵の品質を示さない）。
- `reward_gain_per_1000_actions`: 操作予算に対する学習改善の効率。
- `wall_clock_per_image`, `CLI_calls`, `Evaluator_calls`, `peak_memory`: 実利用可能性。
- `replay_success_rate`: 操作列から画像・作品JSONを正しく再生できた割合。
- `distinct_prompt_success`: 未見の名詞、色、空間関係を含む文章への一般化。
- `image_blind_violations`: Actorに視覚情報が流れた回数。**1件でも不合格**。

### 中止条件・やり直し

- 未見文章で学習なしベースラインを超えない状態が続くときは、大規模学習へ進まずActorの行動表現と報酬を再設計する。
- `reward`だけ上がり人間評価が改善しない場合、採点器ハックを疑い評価器/ペナルティを検証する。
- 高画質で操作数/実行時間が許容できない場合、画像モデルの容量を増す前にコマンド表現とバッチ性能を検証する。
- 画像隔離やライセンス要件を満たさない実験は結果が良くても不合格。性能を優先して例外を作らない。

## 8. 技術的な参考（今回の条件との差）

- [Learning to Paint With Model-Based Deep Reinforcement Learning（ICCV 2019）](https://openaccess.thecvf.com/content_ICCV_2019/html/Huang_Learning_to_Paint_With_Model-Based_Deep_Reinforcement_Learning_ICCV_2019_paper.html): 筆の操作と長期計画の参考。ただし**対象画像・キャンバスをActorが観測する設計**であり、画像非参照という本件の成功例ではない。
- [Learning to write programs that generate images（DeepMind 2018）](https://deepmind.google/blog/learning-to-write-programs-that-generate-images/): 描画プログラムによって画像を作るAIと識別器報酬の考え方の参考。ただし本件のActorの入出力制約とは同一ではない。
- [Unsupervised program synthesis for images by sampling without replacement（UAI/PMLR 2021）](https://proceedings.mlr.press/v161/zhou21b.html): 正解プログラムなしのプログラム探索、構文制約、重複しない探索で疎報酬に対処する考え方の参考。**画像を見ないActorの実証ではない**。
- [B-Spar: Bayesian Sparse-Reward Modeling for RL-based Image Editing（ICML 2026）](https://proceedings.mlr.press/v306/xu26aj.html): 微小な局所修正ばかりを評価する密な代理報酬が知覚品質と乖離し得る、という報酬設計の注意点の参考。**マルチモーダル画像編集**の研究であり、本件の画像非参照仕様と区別する。
