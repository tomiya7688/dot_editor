# 任意解像度と非破壊の保持モデル

## 公開API

`PixelCanvas(width, height=None)` / `LayeredPixelCanvas(width, height=None)` は正の整数解像度を受け付けます。高さ省略時は正方形です。`SUPPORTED_SIZES` は互換用のプリセット一覧であり、入力の制限ではありません。新規呼び出し元は `resolution`（横・縦のタプル）または `width` / `height` を使ってください。旧 `size` は横幅の互換エイリアスです。

```python
from pixel_backend import PixelCanvas

canvas = PixelCanvas(16)
canvas.paint(2, 2, (80, 100, 120, 255))
canvas.set_resolution(7, 7)       # 既定は細部保持
canvas.set_resolution(23, 17)     # 非正方形にも対応
canvas.set_resolution(16, 16)     # 無編集なら元の情報が完全に戻る
canvas.set_resolution(7, 7)
canvas.paint(1, 1, (120, 130, 140, 255), detail_policy="preserve")
canvas.discard_detail(3, 2, width=2, height=1)
canvas.undo()                    # この破棄を戻す
canvas.save_png("fine.png", output_resolution=(23, 17))
```

`resize()` も保持が既定の `set_resolution()` に統一しました。`upscale()` は縦横をそれぞれ2倍にし、保持情報を削除しません。全レイヤーの解像度変更は一括で検証・準備してから反映します。レイヤーの途中で処理が失敗しても一部だけ解像度が変わることはありません。`LayeredPixelCanvas.undo()/redo()` は全レイヤーの解像度、細部、選択レイヤーを一緒に復元します。

`image` は現在の論理解像度へ投影した読み取り用コピーです。直接 `image.putpixel()` で作品を更新せず、`paint` / `fill` / `import_image` を使ってください。

## 保持と破棄の意味

表示・編集用のグリッドと、元の描画情報を分離しています。全体解像度を変えただけでは保持用ラスターパッチも局所分割の情報も変更しません。低解像度の代表色は、セル中心を使った最近傍サンプリングです。平均色への変換ではありません。

通常の粗いセルに `preserve` で描く場合、指定色とそのセル中心の値との差をRGBAのオフセットとして対象領域へ重ねます。元の細かい画素値とその差分は別々に保持され、細部の色の差を残した粗い色変更になります。0〜255の範囲制限は表示時だけに適用するため、保存・再読込を挟んでも元の値は失われません。色が飽和していると、表示上の細部の差が一時的に見えなくなる場合があります。

明示的に `split` したセルについては既存APIの契約を維持します。親セルへのpreserve描画は親の値だけを変更し、独立した子セル値を上書きしません。子セル自体の変更にはchildを指定します。折りたたみは表示状態だけの変更です。全体解像度を切り替えた後、その分割を作った解像度へ戻すと展開・折りたたみ状態も復元します。

`discard` は対象領域の旧パッチの空間的な有効範囲を切り取り、粗いセル値で置換します。対象内の下位詳細は、あとで解像度を戻しても復元しません。Undoした場合だけ旧状態へ戻ります。領域の外側はそのまま残します。

- `set_resolution(w, h, detail_policy="discard")`: 全体を新しい解像度へ統合。
- `paint/fill(..., detail_policy="discard")`: 編集対象だけを置換。
- `discard_detail(x, y, width, height)`: 現在の各セルの代表色を維持して、その領域だけ詳細を統合。

全体解像度変更のdiscardと局所描画のdiscardを同じCUI呼び出しで指定すると両方に適用されます。局所だけを破棄したい場合は、解像度変更（preserve）と編集（discard）を別々に実行してください。

## データ構造と境界

`ResolutionField` は、画像全体を0〜1とした有理数座標、元ラスターパッチ、有効範囲、色オフセットの組を保持します。非整数倍の解像度変更でも保存済み画像の再リサイズは行いません。例えば16と7の境界がずれる場合も、7分の1の境界を浮動小数点に丸めて近くの16分の1へ移動しません。

局所編集では交差領域とその外側を分け、利用しなくなった元ラスターピクセルを切り落とします。入力JSONのパッチは範囲内・非重複・全域被覆を検証します。

正規化されたパッチのまま処理するのが基本です。パッチ数が増えた場合だけ、全境界を正確に表せ、かつ上限内の共通ラスタへ損失なくまとめられるか試します。巨大な最小公倍数ラスタを必須とする方式ではありません。色オフセットを持つパッチはこの自動統合の対象にしません。

## 安全上限

`resolution_field.py` に、プリセットとは別に次の制限を定義しています。

- 1辺: 1〜4096、1枚のラスタ: 最大4,194,304画素。
- 1レイヤーの保持パッチ: 最大4096、保存されるパッチ画素の合計: 最大16,777,216。
- 保持する局所分割: 1レイヤー最大4096、レイヤー数: 最大256。

上限超過はデータを破棄して続行せず、明示的にエラーを返します。局所分割を展開する場合は、2倍の表示ラスタも上限内である必要があります。

## 保存と互換性

保存は `version: 2`。現在の `resolution`、保持用 `retained_field`、各解像度での局所分割 `retained_splits` を記録します。`pixels` と現在解像度の `refined_cells` は投影結果であり、読込時に保持データとの一致も検証します。RGBAは `#RRGGBB` / `#RRGGBBAA` を使い、透明画素の隠れたRGBも保持します。

旧バージョンの正方形JSON、`refined_cells` なしのJSON、`expanded` なしの旧分割JSONを読み込めます。旧形式は読込時に保持モデルへ移行します。**新しいversion 2のJSONは旧版のエディタへ戻して編集しないでください。** 旧読込コードには保持データの扱いがないため、新形式を安全に往復できません。

JSONは描画情報と局所分割の状態を保存します。Undo/Redoの操作スタックはセッション内だけです。非対話CUIの別プロセス間でUndoを共有する機能ではありません。

## PNGとGUI

`render()` / 通常のPNG保存は現在のグリッドと展開状態の表示です。既存の `export --size N` はその表示を正方形へ拡大します。

`render_resolution(w, h)` / `export --resolution W H` は保持している情報から指定解像度へ直接投影します。折りたたみ中の情報を含め、保存データに残っている細部を使います。プロジェクトの現在解像度は変更しません。

GUIには縦横別の解像度入力、保持・破棄の選択、選択セルの折りたたみ・破棄を追加しています。表示の縦横比、ズーム、パンを考慮して、クリック位置を独立に横・縦のセル座標へ変換します。
