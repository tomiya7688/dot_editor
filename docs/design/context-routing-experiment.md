# task-first routerの効果を実セッションで測る実験計画

対象: [Issue #51](https://github.com/tomiya7688/dot_editor/issues/51)。ルーターの現行定義は[タスク別の案内](../agents/README.md)と[task-map](../agents/task-map.md)、静的な候補比較は`scripts/context_route_benchmark.py`です。状態: **計画のみ。実セッションの比較は未実施です。** 静的な比較（候補ファイルのバイト数が89.7%少ない）は、実際の読込量・入力token数・作業時間の削減を示しません。

## 背景・目的

担当者向けの入口（AGENTS.mdとその先の案内）が、実際にAIの作業を速く・正確にするかを、主張ではなく測定で確かめます。品質が下がるなら、案内を直して同じ基準で再評価します。

## 条件を固定するもの

| 項目 | 内容 |
| --- | --- |
| 対象のタスク | T1: Rust project JSON、T2: Python CLI / Command API、T3: GUIのキーボード・メニュー。必須の根拠は`context_route_benchmark.py`の`TASKS`が定義 |
| 開始SHA | 実験開始時の`origin/main`の1コミットを固定し、全試行で同じ |
| 依頼文 | タスクごとに1つ。完了条件（見つけるべき根拠、実行するテスト）を明記。**読取だけの事前調査**で、ファイルを変更しない |
| 条件 | **A**: 案内なしの広域調査（AGENTS.mdの案内を伏せ、検索と読み取りのみ許可）。**B**: AGENTS.mdから案内をたどる |
| エージェント | Claude CodeとCodex。モデルの名前と版、権限、許可ツールを記録して固定 |
| 試行 | 各（エージェント×タスク×条件）で3回。順序は条件が偏らないよう入れ替える |
| 隔離 | 試行ごとに、固定SHAの新しいworktree・新しいセッション。Aの答えをBへ渡さない。記憶や過去の会話を使わない設定にする |

## 採取するもの（取得できるものだけ。取れないものは`unknown`）

| 指標 | 取得元 |
| --- | --- |
| 読んだファイルと範囲、検索・ツールの呼び出し回数、読み直し、失敗 | 各ツールの会話記録（Claude Codeのtranscript、Codexのsessionログ） |
| 経過時間 | 記録の時刻 |
| 入力・出力token（キャッシュの読込/作成を分ける） | 提供元が記録した使用量。**推計で埋めない** |
| 根拠のカバレッジ | 必須の根拠（ソース・テスト・仕様・見本）のうち、実際に確認した割合 |
| 完了条件の達成 | 指定のテストの実行、受け入れ条件の充足 |
| 手戻り | 誤った仕様解釈、やり直し、追加の確認回数 |

集計用に、会話記録から上の指標を抜き出す小さなスクリプト（`scripts/summarize_agent_trace.py`、案）を作り、生ログは保存せず要約だけを残します。

## 判断の基準

- Bが「改善」と言えるのは、(1)根拠のカバレッジがAと同じ、(2)完了条件の達成が同じ以上、(3)手戻りがAを超えない、(4)tokenまたは時間の中央値が小さい、の**すべて**を満たすときです。1つでも欠けたら、削減の成功にしません。
- 試行数が少ないため、中央値と範囲を示し、統計的に有意とは言いません。
- 静的な候補バイト数を、tokenや費用の削減と書きません。

## 結果の報告

Issueのコメントに、固定SHA、エージェントとモデル、タスクごとの表（条件×指標の中央値と範囲）、再現手順、根拠へのリンクだけを載せます。会話の全文、秘密情報、個人情報は載せません。利用者向けのREADMEやAPI資料は編集しません。

## 実施の前提

実際のClaude Code/Codexの実行と使用量の取得が必要です。担当者が自分の環境で両方を起動できない場合は、**未実施**のままにして、理由を記録します（過去の記録のとおり、このIssueは自動では完了しません）。

## 完了条件

3タスク×2エージェント×2条件の結果が揃い、上の判断基準で評価されていること。基準を満たさなければ案内（`docs/agents/`）を直して再評価し、その結果も記録します。
