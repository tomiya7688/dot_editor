# コード索引ツールGraphifyの導入検討（2026-11-06）

結論: **今は導入しない**。すでにあるCodeGraph（ローカル、送信なし）で足りるため。再検討の条件を下に残す。

## 確認した事実（公式READMEを読んだ範囲）

- 目的: コードや文書を知識グラフにして、AIが検索する道具。Claude Codeなどの`/graphify`スキルとして使う。
- ライセンス: Apache-2.0とMIT表記。Python 3.10以上。PyPIの`graphifyy`（yが2つ）を`uv tool install`で入れ、`graphify install`でスキルを登録する。
- コードの解析はローカル（tree-sitter）でLLM不要。文書・PDF・画像の解析にはAIの呼び出しが要る。クラウド版は有料の別サービス。
- 「トークン80%削減」はクラウド版の数字で、OSS版の数字ではない。
- READMEだけでは、Rustへの対応と最近の更新日は確認できなかった。

## 導入しない理由

1. 今の用途（シンボル・呼出元の探索）はCodeGraphで足りている。同じ働きの道具を足すと、読み込む案内と保守が増え、使用量の削減に逆行する。
2. `graphify install`はAIの設定（スキル）を書き換える。個人の共通設定の変更になるため、この作業では行わない。
3. 綴り（`graphifyy`）が紛らわしく、入れる前に配布元の確認が必要。
4. 削減効果の数字はクラウド版のもので、この環境での測定がない。測定していない削減量は主張しない。

## 再検討する条件

- CodeGraphがRustまたはPythonで結果不足になる場面が、2回以上記録されたとき。
- 配布元（PyPIのhashとGitHubのリリース）を確認できたとき。
- 同じ作業をCodeGraphとGraphifyで測り、入力トークンが減ると示せたとき。この場合も秘密・非公開データは入れない。
