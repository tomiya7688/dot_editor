# 軽量GUIとオフライン操作ヘルプの設計

対象：[GUI改善 Issue #67](https://github.com/tomiya7688/dot_editor/issues/67)。利用者に見える要件は[ユーザー操作インターフェース仕様](../ユーザー操作インターフェース仕様.md)を正本とします。既存Tkinter GUIを活かす追加設計であり、**新画面やHelpメニューが現時点で実装済みとは主張しません**。

## GUI状態と作品を切り離す

- 作品: Python `PixelCommandAPI` が保存・編集するJSON v2/画素/レイヤー/保持細部。GUIのヘルプ操作・画面レイアウト変更はこの状態を変更しません。
- 表示状態: ウィンドウ、キャンバス表示、ズーム/パン、サイドバーの展開、カーソルとフォーカス。
- 入力状態: 選択中ツール、色、押下キー、ダイアログ。フォーカスを失ったら押下状態を戻す。
- オフラインヘルプ: 読取専用の同梱`COMMANDS.md`と`commands.json`を参照する。GUI起動時に大量パーサーを実行/ネット取得しません。

## 初回導線

1. **作品を作る**・**作品を開く**・**最近作業した作品**（存在すれば）を分かるラベルで提示。自動でファイルを削除しない。
2. 画面中央にキャンバスを確保。常時見えるのはブラシ・消しゴム・スポイト・塗りつぶし・色・レイヤーの基本操作、保存/PNGの安全な導線。
3. セル分割や保持/破棄は詳細操作のまとまりに分類し、操作時には親・子・保存情報への影響を短く表示する。破棄・リセットは確認可能にする。
4. メニューの`ヘルプ`から「基本操作」「キーボード」「CLIコマンド表」へ。パッケージ内の参照先が無ければ理由を明示し、CLIの操作を推測して表示しない。
5. 小画面と拡大表示時はサイドバーをスクロール可能にし、重要な状態/保存の導線が画面外へ隠れない。

## 性能・配布・確認

- Tkinter・Pillow以外のGUI依存を増やさず、起動中にネットワーク接続を要求しません。
- ヘルプはread-only・ローカルのファイル/パッケージデータを開く方式とし、任意URLや外部プログラムの実行をヘルプ閲覧で行いません。
- ヘルプから参照するカタログは同じ配布物のCLI実装/バージョンを持つものだけを使用（カタログの生成/同梱は#66）。
- 作品作成/編集/保存→ヘルプを開く→閉じる→Undo/Redo→JSON/PNG再読込までの状態不変を自動テスト。menu・フォーカス・キーボード長押し・ダイアログを含む実GUIテストは#26〜#30で別に確認。
- 起動時間/メモリはリファクタ前後で同じ環境・同じ作品サイズで測定し、数値を取得できない場合は未検証と明記。headless smokeでは実ウィンドウの読みやすさを証明できません。

本書は画面・ヘルプの設計文書であり、エージェントの共同作業規約やIssue運用ルールを利用者に表示することを要求しません。

## 画面構成の固定案（現行実装との差異）

現行`PixelEditor`はデフォルト1040×740、最小900×640、キャンバスと幅約240pxの縦スクロールサイドバーを持つ。`menu_spec()`には現時点で「ファイル・編集・描画・レイヤー・色・表示」の**6メニュー**がある。実際のGUIに「ヘルプ」はまだない。

| 領域 | 常時見える内容 | 操作時のみ表示 |
| --- | --- | --- |
| キャンバス（最優先） | 作品、現在の選択位置、表示倍率 | 選択中セルの子セル編集や詳細情報 |
| 固定のファイル操作 | **新規・開く・保存・PNG書出し** | 上書き確認、保存先の選択 |
| 基本ツール | **ブラシ、消しゴム、スポイト、塗りつぶし、色** | 詳しいツールオプション |
| レイヤー | 現在のレイヤー名、表示/非表示、追加 | 並び替え、改名、削除 |
| 高度な編集（折りたたみ可能） | 「細部・解像度」見出しと現在の保持/破棄状態 | セル分割、折りたたみ、細部破棄、論理解像度変更 |
| ステータス | ツール・選択レイヤー・論理解像度・表示倍率 | 保存状況、エラーや処理結果 |
| ヘルプ | **ヘルプ (H)**メニュー | 基本操作、キーボード、CLIコマンド表 |

「固定のファイル操作」を縦スクロールの深い場所だけに配置しない。スクロールや折りたたみで最重要の操作が消えないよう、メニューと固定ツールバーなど複数の到達手段を設ける。サイドバーの短いラベルは必要な場合に説明文・ツールチップで補い、アイコン単独にしない。

初期窓の操作対象は画面内から見切れないこと。最低限**900×640、1040×740、1024×768、DPI 125%/150%**の環境を検証する。縮小できないときも操作はサイドバーのスクロール、Tab、Altメニューから到達できること。スクロール位置やツールチップがキャンバスの描画イベントを遮らない。

## 作品とUI状態：厳密な所有区分

| 状態 | 正本・責務 | 保存形式への影響 |
| --- | --- | --- |
| 画素、レイヤー、分割/保持細部 | 既存`LayeredPixelCanvas` / `PixelCommandAPI` | 作品JSON v2とPNGへ影響 |
| 選択ツール、表示ズーム、パン、サイドバー展開 | TkinterのUI状態 | 作品JSONへ絶対に混入しない |
| キーボードフォーカス、カーソル、ヘルプタブ | UI/入力コントローラ | Undo/Redo履歴を作らない |
| 作品パス、保存済みcheckpoint、未保存表示 | ドキュメント・セッション状態 | 作品JSON構造へ勝手に追加しない |
| ヘルプのカタログ/言語 | **同梱の読取専用resources** | 保存/描画コマンドを発行しない |

現在のGUIコードが`self.backend`と`self.commands`を使用していることを維持し、GUIの都合だけでRust Coreの保存形式へ独自フィールドを追加しない。GUI画面の描画はCoreを通した編集と、Tk上の表示更新を分離する。

### 作品ライフサイクルの状態機械（新規実装）

```text
起動 → 無題の初期作品（未保存パスなし）
無題/保存済み作品 --編集で実際に変化--> 未保存あり
未保存あり --保存成功--> 保存済み（checkpoint更新）
未保存あり --新規/開く/終了--> 保存確認（保存/破棄/キャンセル）
保存確認 --キャンセル--> 元の作品・パス・Undo/Redo・フォーカスを維持
保存確認 --保存失敗--> 元の作品を維持し、確認待ちに戻る
保存確認 --破棄を選択--> 要求した新規/開く/終了だけ進める
保存済み --ヘルプ/ズーム/パン/表示サイズ変更--> 保存済みのまま
```

- **新規作品**は「作品をリセット」と別の明確な操作。無題作品から保存を選んだ場合は「名前を付けて保存」に誘導する。リセットは既存の破壊操作の確認を維持する。
- 保存確認の初期選択は**キャンセル**。ウィンドウを閉じるXボタン、キーボード操作、別作品を開く場合にも同じルールを適用する。保存失敗やファイルダイアログをキャンセルした場合も元作品を失わない。
- `dirty`は実データの変更だけで立て、ツール切替や表示操作で変更しない。Undoで保存済み状態へ戻ったかどうかは保存したcheckpointとの**意味的等価**を必要時に比較する。各マウス移動で全JSONを直列化して性能を落とさない。誤って「保存済み」と見せるfalse negativeは許さない。
- 保存処理とUI状態切替は非同期/失敗の順序も考慮し、確定に失敗した新しいパスを「保存済み」と記録しない。ファイルの読み込みに失敗した場合は既存作品・履歴・パスが完全に残ること。

## オフラインヘルプの画面契約

`menu_spec()`へ**「ヘルプ (H)」**を追加（既存の6トップ階層とアクセスキーが衝突しない）。子項目は**基本操作・キーボード・CLIコマンド表・バージョン情報**。GUIからOSの外部ブラウザやShellコマンドを起動せず、Tkinterの読み取り専用`Toplevel`・`Text`＋スクロールなど既存の標準UI部品で表示する。

1. 「ヘルプ」を開くと**同梱した資料だけ**を読み取る。初回起動時にMarkdown全体を解析せず、画面を開いた時に必要部分をロード。ヘルプの本文や検索結果をコマンドとして実行しない。
2. **基本操作**：新規→ブラシで描画→レイヤー→作品JSON保存→PNG出力。**キーボード**：現行で使用可能なAlt/Tab/F6/Ctrl+Zのみ表示し、#28/#29で未実装の矢印セル移動/Space描画を「使用可能」と書かない。
3. **CLIコマンド表**：同じ配布物のPython版`commands.json`、`COMMANDS.md`のみ読み込む。画面は目的別の概要と検索/選択で詳細を表示し、`--project`などの引数と副作用・使用例を読める。実装中のRust版コマンドを現行Windows Python版として表示しない。
4. 表示時は`cli_implementation`、`cli_version`、`schema_version`を確認する。Python Frozen版とwheelインストール版で資料の参照ルートを明確に区別し、**作業ディレクトリにある同名ファイルを無断採用しない**。`importlib.resources`等のパッケージ正規入口を使用する。
5. 同梱資料が不足/破損/版不一致なら「この版のヘルプを表示できません」と表示し、必要ならCLI本体の既存`--help`コマンドを案内する。**GUIから実行して補完したり、無関係なRust/Python資料へ自動フォールバックしない**。配布CIでは資料欠落が検出され、そもそも正常なReleaseを作れないこと。
6. ヘルプは非モーダルを基本とし、Esc/閉じるで**開く前にフォーカスしていたWidgetへ復帰**。未保存フラグや作品履歴が変わらない。ヘルプ中の検索欄で入力した矢印・Space・Ctrl+Zは作品に作用しない。
7. 長文はスクロール可、検索結果なしの場合は明示する。タブ切替時のスクロール位置は各タブごとに保持してよいが、プロジェクトへ保存しない。

### 読み込み経路（実装順）

```text
GUIヘルプ操作
  → ヘルプリソース解決（インストール形態を確認）
  → schema/version/implementationチェック
  → 読取専用の軽量モデルに必要範囲をロード
  → Tkinter Text/一覧/検索の表示
  → 閉じると描画・パス・履歴を変更せず前Widgetへ戻る
```

オフラインヘルプはインターネット接続を禁止し、外部URLの自動取得、任意HTMLのレンダリング、ローカルユーザー指定ファイルの実行を伴う仕組みを導入しない。資料を開く目的だけのネットワーク/サーバー起動も禁止する。

## フォーカス・アクセシビリティと性能

- **F6/Shift+F6**のキャンバスとサイドバー切替を維持。サイドバーの新しいボタンを`register_sidebar_focus_target`等の既存管理へ追加し、Tab/Shift+Tabで飛び越さない。新しいヘルプトップメニューはAlt+Hで到達。
- キャンバスに描画フォーカスがある場合だけ将来のSpace/矢印キー描画を扱う（#28～#30）。テキスト入力中のSpace・矢印・Ctrl+Zは入力欄が優先。
- 状態表示を色だけに依存させず、選択ツール/レイヤー/保持か破棄かを文字でも表示。ヒントはキー操作でも確認でき、ヘルプはスクリーンリーダーの実検証なしに完全対応を宣言しない。
- Tkinter/Pillowの既存依存の範囲でUIを改善し、Chromium/WebView/常駐サーバーを新たな必須要件にしない。起動時間とアイドル時RSSは同じ環境・同じ作品・同じ計測手順で**変更前後を5回以上**測定して中央値と外れ値を報告。未計測値を`0ms`扱いしない。
- ヘルプを開閉している間に、作品JSON、選択中のレイヤー、Undo/Redo、表示ズーム/パンの状態が勝手に変わらないこと。

## 実装分割・受け入れケース #67

| 作業 | 対象 | 完了に必要な確認 |
| --- | --- | --- |
| GUI-A | ファイル操作の固定導線・新規とリセットの分離・dirty/checkpoint | 新規/開く/保存/破棄/キャンセル全分岐で作品保護 |
| GUI-B | 基本ツールと詳細編集欄の階層化 | 900×640とDPI拡大でも全操作へ到達 |
| GUI-C | ヘルプ(H)と読取専用資料表示 | Help→検索→閉じる→元フォーカス、作品/履歴不変 |
| GUI-D | 資料のschema/実装版検証 | 同梱Python版だけ表示。欠落/別版は明示エラー |
| GUI-E | GUIイベント/統合テストとWindows EXE実検証 | headlessは状態遷移、実GUIは視認性/操作通しを記録 |

具体的な回帰試験は次の通り。

| ID | 条件 | 期待結果 |
| --- | --- | --- |
| GUI-01 | 未保存編集後に新規・開く・終了でキャンセル | 作品、履歴、保存先、フォーカスが変わらない |
| GUI-02 | 未保存編集から保存失敗 | 元の状態を維持し保存済み表示をしない |
| GUI-03 | 保存成功後にツール/ズーム/パン/Helpを操作 | dirty/JSON/履歴が変わらない |
| GUI-04 | 保存後編集→Undoで保存時点へ戻る | dirty判定が保存checkpointと整合する |
| GUI-05 | 同梱Python catalogをHelpから開く | command数、バージョン、実装種別が一致する |
| GUI-06 | Rust catalogをPython配布物に入れる | 誤版を表示せず、明確なエラー |
| GUI-07 | カタログが破損/欠落/未知schema | オフラインの案内エラー、作品は不変 |
| GUI-08 | ヘルプ中の検索入力と閉じる | キーがキャンバス描画に作用せず元フォーカスへ |
| GUI-09 | Alt+H、Tab/F6、細部欄の展開 | 全項目へキーボード到達可、アクセスキー衝突なし |
| GUI-10 | 最小窓・DPI拡大・多数レイヤー | 重要な保存/編集操作が到達不能にならない |
| GUI-11 | Windows配布EXEで画面操作 | 実ダイアログ・ヘルプ・スクロール・見やすさを確認 |
| GUI-12 | CLI機能がまだ未実装 | GUIヘルプに使用可能コマンドとして現れない |

GUI-A～Eを一つの巨大差分で実装しない。#66の成果物resourcesと#26～#30のキーボード実装に依存する部分を明記し、受け入れ済み機能は壊さず段階的にマージする。本書は**実装完了の宣言ではない**。
