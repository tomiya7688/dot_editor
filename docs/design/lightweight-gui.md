# 軽量GUIとオフライン操作ヘルプの設計

対象：[GUI改善 Issue #67](https://github.com/tomiya7688/dot_editor/issues/67)。利用者に見える要件は[ユーザー操作インターフェース仕様](../ユーザー操作インターフェース仕様.md)を正本とします。既存Tkinter GUIを活かす追加設計であり、**新画面やHelpメニューが現時点で実装済みとは主張しません**。

## GUI状態と作品を切り離す

- 作品: Python `PixelCommandAPI` が保存・編集するJSON v2/画素/レイヤー/保持細部。GUIのヘルプ操作・画面レイアウト変更はこの状態を変更しません。
- 表示状態: ウィンドウ、キャンバス表示、ズーム/パン、サイドバーの展開、カーソルとフォーカス。
- 入力状態: 選択中ツール、色、押下キー、ダイアログ。フォーカスを失ったら押下状態を戻す。
- オフラインヘルプ: 読取専用の同梱`COMMANDS.md`と`commands.json`を参照する。GUI起動時に大量パーサーを実行/ネット取得しません。

## 初回導線

1. **作品を作る**・**作品を開く**・**最近作業した作品**（存在すれば）を分かるラベルで提示。自動でファイルを削除しない。
2. 画面中央にキャンバスを確保。常時見えるのはブラシ・消しゴム・スポイト・塗りつぶし・色・レイヤーの基本操作、保存/PNGの安全な導線。
3. セル分割や保持/破棄は詳細操作のまとまりに分類し、操作時には親・子・保存情報への影響を短く表示する。破棄・リセットは確認可能にする。
4. メニューの`ヘルプ`から「基本操作」「キーボード」「CLIコマンド表」へ。パッケージ内の参照先が無ければ理由を明示し、CLIの操作を推測して表示しない。
5. 小画面と拡大表示時はサイドバーをスクロール可能にし、重要な状態/保存の導線が画面外へ隠れない。

## 性能・配布・確認

- Tkinter・Pillow以外のGUI依存を増やさず、起動中にネットワーク接続を要求しません。
- ヘルプはread-only・ローカルのファイル/パッケージデータを開く方式とし、任意URLや外部プログラムの実行をヘルプ閲覧で行いません。
- ヘルプから参照するカタログは同じ配布物のCLI実装/バージョンを持つものだけを使用（カタログの生成/同梱は#66）。
- 作品作成/編集/保存→ヘルプを開く→閉じる→Undo/Redo→JSON/PNG再読込までの状態不変を自動テスト。menu・フォーカス・キーボード長押し・ダイアログを含む実GUIテストは#26〜#30で別に確認。
- 起動時間/メモリはリファクタ前後で同じ環境・同じ作品サイズで測定し、数値を取得できない場合は未検証と明記。headless smokeでは実ウィンドウの読みやすさを証明できません。
