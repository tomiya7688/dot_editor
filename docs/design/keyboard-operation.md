# GUIのキーボード操作（メニュー・フォーカス・セルカーソル・Space描画）の詳細設計（未実装）

対象: [Issue #26](https://github.com/tomiya7688/dot_editor/issues/26)（メニュー）、[#27](https://github.com/tomiya7688/dot_editor/issues/27)（フォーカスとダイアログ）、[#28](https://github.com/tomiya7688/dot_editor/issues/28)（セルカーソル）、[#29](https://github.com/tomiya7688/dot_editor/issues/29)（Space描画）、[#30](https://github.com/tomiya7688/dot_editor/issues/30)（通し検証）。前提の不具合は[#75](https://github.com/tomiya7688/dot_editor/issues/75)。ヘルプやAlt+Hの導線は[軽量GUIの設計](lightweight-gui.md)（#67）と共有します。状態: **設計案であり、実装済みではありません。** 現状の記述は2026-11-05時点の`src/dot_editor.py`をソースで確認したもので、実際の画面での確認は含みません。

## 背景・目的・利用者の入口

マウスを使えない利用者や、キーボードで素早く描きたい利用者が、作品の新規作成から保存までを、キーボードだけで完結できるようにします。入口は次のとおりです（利用者の操作）。

1. **Alt**を押してメニューを開き、アクセスキーで項目を選びます（#26）。
2. **Tab / Shift+Tab**で要素を移り、**F6 / Shift+F6**でキャンバスとサイドバーを行き来します（#27）。
3. キャンバスで**矢印キー**を押してセルを選び（#28）、**Space**で塗り、Spaceを押したまま矢印を押し続けて線を引きます（#29）。

## 部品の分け方（責務）

| 部品 | 責務 | Tkに依存するか |
| --- | --- | --- |
| `CanvasCursor` | 選択中のセル位置と子セル、移動と範囲内への補正。作品を変更しない | しない（単体テスト可能） |
| `StrokeSession` | Space・移動キーの押下状態、描画するセルの経路、取り消しの条件 | しない |
| `FocusMap` | フォーカスする領域と要素の一覧、復帰先の決定 | しない |
| `run_dialog` | ダイアログを開く前にフォーカスと押下状態を保存し、閉じた後に復帰する共通の入口 | 薄く依存 |
| GUIアダプタ（`dot_editor.py`） | Tkのイベントを上の部品へ渡し、結果を描画・コマンドAPIへ反映する | する |

作品への編集は、これまでどおり共通Command API（`perform_edit`）だけを通します。カーソルと押下状態は**作品データの外**にあり、JSON・PNG・履歴に入りません。

## #27 フォーカスとダイアログ

### 操作要素の棚卸し（到達・実行・戻り）

| 領域 | 要素 | 到達 | 実行 | 戻り |
| --- | --- | --- | --- | --- |
| メニュー | 全項目 | Alt、アクセスキー | Enter | Esc/実行後に呼び出し元 |
| キャンバス | 描画面 | F6、Tab | 矢印・Space・Enter・Esc | Tab/F6 |
| サイドバー | ツール4、セル操作3、色ボタン、パレット8 | F6、Tab | Space/Enter | Tab/F6 |
| サイドバー | レイヤー一覧と6ボタン | Tab、矢印（一覧） | Space/Enter | 同上 |
| サイドバー | 保持/破棄の選択、解像度・表示・拡大の各ボタン | Tab、矢印（選択） | Space/Enter | 同上 |
| サイドバー | 元に戻す、やり直す、読込、保存、PNG、リセット | Tab | Space/Enter | 同上 |

マウスが必須の要素を**ゼロ**にします。確認は上の表と実際のウィジェット一覧を突き合わせるテストで行い、表に無い操作可能要素が増えたら失敗にします。Tabの順序は画面上の並びと一致させます（現状は作成順で、未検証）。

### ダイアログ

| 種類 | キーボードでの確定/取消 | 復帰 |
| --- | --- | --- |
| ファイル・色（OS標準） | OSの標準操作（Enter/Esc）。使えない部分があれば、色は「パレットから選ぶ」を代替導線とする | 呼び出し元 |
| 文字列・整数 | Enter/Esc | 呼び出し元 |
| はい/いいえ | 既定は「いいえ」（リセット・破棄確認）。Enter/Esc | 呼び出し元 |
| エラー表示 | Enter/Esc | 呼び出し元 |

すべてのダイアログを`run_dialog`経由にし、`parent`を必ず指定します。`run_dialog`は(1)現在のフォーカス要素と押下状態を保存、(2)ストロークの取消、(3)ダイアログ実行、(4)要素が有効なら復帰、無効（削除された等）なら隣の要素、なければキャンバスの順で復帰します。入力欄では`Space`・矢印・`Ctrl+Z`をグローバル処理が奪いません（既存の文字入力判定を維持。日本語入力の変換中のキーは入力欄が処理する）。

フォーカスの枠は現行の水色（`#80d4ff`、2px）を基準にし、暗い背景でも見えることを実画面で確認します。画面外のサイドバー要素への移動で自動スクロールする既存の動作を維持します。

## #28 セルカーソル

- `CanvasCursor`は、位置`(x, y)`（作品の論理解像度での座標）と、子セルのモードの有無`child=(cx, cy)`を持ちます。`selected_cell`はカーソルと一本化し、クリックでもカーソルが動きます。
- 移動は作品・履歴・保存データを変えません。端では止まります。キーを押し続けたときの連続移動は、OSのキーリピートによる`KeyPress`の繰り返しをそのまま使います。
- 表示は、キャンバス上の別アイテム（`cursor`タグ）で二重の輪郭（明・暗）として描きます。書き出しは作品のデータから描くため、PNG・JSONに入りません。カーソルが画面外になったら、キャンバスをスクロールして見える位置に追従します。座標とキャンバス位置の変換は、`paint_pixel`の逆変換（拡大率・原点・非正方形）を共通関数にして使います。
- 子セル: 展開済みの分割セルの上で`Enter`を押すと、そのセルの2×2の子セルだけを矢印で移動します。端で矢印を押すと子セルのモードを抜けて隣の親セルへ移ります。`Esc`でも抜けます。折りたたまれたセルでは入れず、状態表示に理由を出します。
- カーソルの補正: レイヤーの切替、読込、リセット、解像度の変更、元に戻す/やり直しの後に、`clamp()`で範囲内へ戻します。子セルが消えたら親セルへ戻します。
- 矢印はキャンバスのウィジェットにバインドします。メニュー・入力欄・サイドバーにフォーカスがあるときは動きません。

## #29 Space描画とストローク

### 状態

`idle`（何も押していない）→ `space_down`（Space押下、現在のセルを塗った）→ 移動キーの`KeyPress`ごとにカーソルが動き、動いた先を塗る → Spaceの`KeyRelease`で`idle`。移動キーだけを押しているときはカーソルが動くだけで塗りません。Spaceと移動キーの押す順は問いません（矢印を押したままSpaceを押しても、その時点のセルを塗る）。

- 塗る経路: 1回のイベントで複数セル進んだ場合（処理遅れ）に穴が空かないよう、前に塗ったセルから新しいセルまで直線で補間します。補間は作品の座標系で行い、範囲外には出ません。
- キーリピートの差: Windowsでは押している間`KeyPress`が繰り返されますが、環境によっては`KeyRelease`と`KeyPress`の組が繰り返されます。`StrokeSession`は「実際に離された」ことを、短い確認時間（数十ミリ秒）内に再度押されなかったときだけ確定し、二重描画と途切れを防ぎます。移動の速さはOSのキーリピート設定に従います。
- ツール別: ブラシ/消しゴムはストロークで連続して適用します。塗りつぶし・スポイトは、Spaceを**押した瞬間の1回だけ**適用し、リピートでは繰り返しません（適用後にブラシへ戻る既存の動作を維持）。
- 取消の条件（押下状態とタイマーを解除し、再開しない）: フォーカスを失う、Alt/F10でメニューへ移る、ダイアログを開く（`run_dialog`）、ウィンドウが非アクティブになる、リセット・読込、ツールの変更。フォーカスを失った時点で、押下しているとみなすキーの集合を**空にします**（離されたかどうかを後から知る手段がないため）。復帰後は、新しい`KeyPress`で`Space`が届くまで描画しません。
- ストローク中のツール: ストロークは、Spaceを押した時点のツールで最後まで行います。ストローク中にツールが変わる操作（メニュー、サイドバー）はフォーカスの移動を伴うため、上の取消の条件で必ずストロークが終わり、途中でツールが切り替わることはありません。
- 離したことの判定: 判定に使うのは、Spaceの`KeyRelease`と、その直後の確認時間（既定30ミリ秒）内に同じキーの`KeyPress`が来ないこと、の2つだけです。単独のタイマーで「押している」と推測せず、イベントの順序（`KeyRelease`→`KeyPress`の対）を受け入れ条件のテストで固定します（Windowsの連続`KeyPress`、X11型の対、取りこぼしの3種のイベント列）。
- キャンバス以外のSpace: ボタンの実行や文字入力として働き、グローバルには処理しません。

### 履歴（ストローク単位）

`edit_transaction()`を導入し、Spaceの押下から解除までを**1回の取り消し**にします。内部では、開始時に1回だけ編集前の状態を保存し、各セルの描画は共通Command APIで行い、終了時に変更があれば1件だけ履歴へ積みます。何も変わらなければ履歴を増やしません。マウスのドラッグ（ボタンを押してから離すまで）にも同じ`edit_transaction()`を使うと、取り消しの粒度がキーボードと揃い、現在の「セルごとに1件」が「1回のドラッグで1件」に変わります。**これは既存のマウス操作の挙動変更で、Issue #29の要件の範囲外です。** 所有者の承認を得るまで適用せず、キーボード側（Space描画）だけを先に実装します。承認後に別のPRで適用し、READMEの変更点に記載します。

描画は、選択中のレイヤー、カーソルのセルまたは子セル、現在の「細部を保持/破棄」の設定に従います。保存・再読込後の**描画結果**はマウス描画と同じです。

## 未決・リスク

- Tk標準のメニューのAlt/F10の動きと、メニューを閉じた後のフォーカスの戻り方は、実画面で確認するまで確定しません（確認の結果によって`run_dialog`相当の復帰処理を追加します）。
- キーリピートの`KeyRelease`の挙動はOSで異なります。Windows配布EXEを主対象とし、他のOSのGUI配布は現時点ではありません。
- マウスの取り消しの粒度（上の4b）は、所有者の指示により変更済みです。ブラシと消しゴムのドラッグは、ボタンを押してから離すまでが1回の取り消しになります（以前は塗ったセルごとに1件）。ボタンの離しを取りこぼしても、次の押下で前のドラッグを確定します。塗りつぶしとスポイトは1回のクリックで1件のままです。
