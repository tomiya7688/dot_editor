# 設計書の一覧（Issueから設計書へ）

担当者が「このIssueの設計はどれか」を最初に探すための一覧です。実装の前に、対応する設計書を読んでください。設計書がないIssueは、先に[設計書の書き方](../../doc/ワークフロー/設計書.md)に従って書きます。更新日: 2026-11-05。

## 状態の意味

| 状態 | 意味 |
| --- | --- |
| 実装済み | 設計と実装が一致し、テストがある。文書は現行の挙動を説明する |
| 設計案 | 設計を確定したが、実装していない。文書の冒頭に「未実装」と書く |
| 方針 | 実装ではなく、判断の基準や手順（運用）を定めた文書 |
| 履歴 | 当時の評価記録。実装の優先順位としては使わない |

## この一覧の保ち方

- 設計書を足したら、この一覧に1行足します（`Agent policy`のチェックが、一覧にない設計書を検出します）。
- 状態が変わったら（設計案→実装済み）、設計書の冒頭の「状態」と、この一覧を同じPRで直します。
- 実装していない機能を、現行の挙動として説明する節に書きません。
